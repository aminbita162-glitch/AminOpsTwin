       Revocation is an audited event that increments policy_epoch.

       In-flight work is re-authorised immediately before COMMIT_INTENT. If

       verified offline. Audit storage is write-once: no role may UPDATE or
       DELETE. If anchoring lags by more than 1 hour, new commits are
       refused (fail closed). Only identifiers and hashes are stored.
       Proof: tampering and deletion are detected; receipts verify offline.
       Implementation: storage in P27, signing and timestamping in P32.

       treated as a success, and it is never blindly retried. A reconciler

       are blocked until resolution. UNKNOWN is visible on the dashboard,

PHASE P34 - CONNECTORS AND SHADOW MODE
==============================================================================

STATUS            NOT_STARTED

OBJECTIVE
  Connect the twin to real operational data for the first time,
  exclusively through aggregate channels, with full data sovereignty, and
  with no effect ever written to a customer system.

PRECONDITIONS
  - P33 merged.

INPUTS
  ADR-004, ADR-008; ingestion/; contracts/data_contract.py; evidence/
  ingestion.py; assurance/drift.py; agents/ (A1)

  pyproject.toml, uv.lock, reports/P34/

FORBIDDEN PATHS
  directive.txt, docs/adr/, LICENSE

AUTHORISED DEPENDENCIES
  defusedxml, lxml with safe parser settings (runtime)
  openpyxl in read-only mode (runtime)

DELIVERABLES
  1. Connector framework. Every connector is a plugin with a manifest:
     name, version, data classes produced, region, authentication method,
     and declared egress endpoints. Connectors run isolated, with network
     access limited to their declared endpoints. All data passes through
     the ingestion gateway and the data contract.
  2. Aggregate-at-source rule (charter clause 18):
       - The system accepts only aggregate operational data.
       - Field-level allowlist.
       - Any patient-level field causes the whole payload to be rejected,
         quarantined as an opaque hash, and alerted. Its content is never
         persisted.
       - Counts below 5 are suppressed.
  3. CDISC ODM import (study metadata only):
       - Accept only the ODM Study and MetaDataVersion structure.
       - Any document that contains a ClinicalData or ReferenceData element
         is rejected in full, before any element content is parsed.
       - Operational counts (open queries, completed visits per site and
         period) are accepted only as separately supplied aggregate
         exports.
       - XML hardening: no external entities, no DTD processing, an
         expansion limit, a size cap, and XSD validation.
  4. Aggregate exports from operational systems (CSV and XLSX):
       - mapping templates;
       - A1-assisted column mapping with human confirmation;
       - strict schema validation.
  5. A generic REST connector for operational-system APIs, contract-tested
     against a mock server. No compatibility with any named vendor is
     claimed until it has been tested against that vendor.
  6. Real Shadow mode:
       - twin predictions are compared side by side with the received
         aggregates;
       - no effect is written anywhere;
       - a calibration report (MAPE, and confidence-interval coverage);
       - drift detection.
  7. Data contract v3:
       - per-field provenance (source system, extraction time, connector
         version);
       - mandatory data-class and region labels (ADR-008).
  8. Reliability:
       - incremental sync with watermarks;
       - idempotent ingestion (ADR-004);
       - backoff and a dead-letter queue;
       - schema-drift detection: unknown fields are quarantined, never
         dropped silently.
  9. Security:
       - connector credentials are held in the key-management store;
       - read-only, least-privilege scopes;
       - a per-connector egress allowlist.
