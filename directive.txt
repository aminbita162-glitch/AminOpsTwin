P16 — BIT-REPRODUCIBLE DETERMINISTIC SUBSTRATE
================================================================================
Entry: P15 verified and owner has instructed P16.

Required:

1. Replay Engine
   - Implement a checkpoint format (canonical bytes + signature placeholder) that captures Executor and Twin state.
   - Provide resume_from_checkpoint(path) that restores state and continues; final state hash must equal a fresh run.
   - Acceptance: test that runs N steps, checkpoints, resumes, and asserts identical hash.

2. Cross-platform oracle
   - CI matrix job (ubuntu-latest and macos-14 or equivalent ARM) runs a fixed workload and compares state hashes.
   - On mismatch, emit a structural diff.
   - Acceptance: both platforms produce identical hash on the reference workload.

3. Mandatory advanced testing
   - CI runs a defined subset of Hypothesis property tests and a mutation check on gateway/ with a minimum score threshold documented in gates.yaml.
   - Acceptance: CI fails if threshold not met.

4. Integer simulation time
   - MilliMinuteClock (or equivalent) supports a configurable working calendar (list of non-working intervals) using only integer arithmetic.
   - Acceptance: advancing across a non-working interval skips correctly; no float used.

5. Fixed-point numeric type
   - Introduce a Fixed scalar type (scaled integer) for any field that enters a hash. Provide conversion helpers and ban float in those paths via test.
   - Acceptance: round-trip and aggregation tests pass; float detection test fails the build if violated.

6. Canonical serializer differential
   - Maintain the existing canonical JSON serializer. Add a second pure-Python reference implementation or a large corpus differential test (≥10 000 random + fixed vectors) that asserts byte equality.
   - Acceptance: differential test passes.

7. Deterministic RNG
   - Named streams derived by H(seed || stream_id). Sequences identical across processes and architectures.
   - Acceptance: cross-process and (via CI) cross-platform equality.

8. Simulation validation
   - Tests against at least two analytical references (e.g. Erlang-C waiting time, Little’s Law) with pre-declared relative error thresholds.
   - Acceptance: measured error ≤ threshold.
